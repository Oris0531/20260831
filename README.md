# AI 客訴分流處理系統 (AI Customer Complaint Triage System)

> **AI 時代的專案管理師養成班 — 專題個人成果展現**  
> 一套兼具「前台智慧引導」、「中台客服協作」與「後台營運監控」的全流程客訴分流與危機處理解決方案。

---

## 📌 專案簡介 (Overview)

在現代客戶服務場景中，客服團隊常面臨「一般性重複問題耗費大量人力」與「高風險/情緒化客訴未能第一時間介入導致危機擴大」的雙重挑戰。

**「AI 客訴分流處理系統」** 採用三層智能分流架構，透過標準化知識庫引導、NLP 風險語意偵測引擎與即時工單派送機制，達到：
1. **常見問題秒級自助化**：降低 60%+ 重複性客服諮詢負擔。
2. **中低風險工單自動化**：建立追蹤單號與聯絡資訊，實現標準化排單處理。
3. **高風險危機即時攔截**：偵測客訴情緒關鍵字與強烈語氣，無縫轉接人工客服並啟動即時對話，脈絡零遺漏。

---

## 🌟 核心特色亮點 (Key Features)

### 1. 🎯 三階段智能分流機制 (3-Tier Intelligent Triage)
系統建立層層遞進的服務分流漏斗，精準配置客服資源：
- **第一層｜知識庫自助解答 (Self-Service FAQ)**：涵蓋 6 大常見客訴類別與實務案例庫，引導用戶自助排查並提供即時標準處置方案。
- **第二層｜中低風險自動開單 (Automated Ticket Dispatch)**：若知識庫未解決且情緒平穩，系統自動蒐集用戶姓名、電話與詳細描述，生成標準工單號碼（如 `CT-2026-0101`）排入待辦清單（狀態標記為「處理中」）。
- **第三層｜高風險即時轉人工 (High-Risk Instant Escalation)**：觸發風險關鍵字或強烈情緒時，系統同步建立工單（狀態標記為「轉人工處理中」）並發出紅色警報轉入待接手隊列，優先由專人介入處理。

---

### 2. 🧠 NLP 風險與情緒感知引擎 (Sentiment & Risk Analysis Engine)
內建智能文本分析規則，於用戶提交描述時進行毫秒級判斷：
- **敏感關鍵詞識別**：精準捕捉法律爭議（`提告`、`消保官`）、服務爭執（`退費`、`爛`、`誇張`、`火大`）及情緒謾罵等 19+ 組核心高風險字詞。
- **標點語氣強度計算**：分析連續驚嘆號（如 `!!!`）與標點密度，評估客戶憤怒指數與緊急程度。
- **視覺化風險標籤**：於客服端後台自動掛載標籤（如 `關鍵字：提告`、`驚嘆號 ×3`），協助客服秒懂風險重點。

---

### 3. 🔄 全鏈路脈絡無縫交接 (Full-Context Handover)
解決傳統客服「轉接後客戶需重講一遍」的痛點：
- **查閱歷程透明化**：客服接手後可完整檢視「客戶選取類別」、「曾查詢的 FAQ 案例」、「系統原先給予的解答」及「客戶自填的具體描述與聯絡方式」。
- **決策輔助資訊**：提供即時背景資訊，讓客服第一時間掌握客戶核心訴求，大幅提升處理滿意度。

---

### 4. 💬 整合式雙向即時對話系統 (Interactive Live Chat)
- **接手即連線**：客服人員於待接手隊列點擊「標記為已接手」後，系統立即在客戶端與客服端同步啟用即時對話視窗。
- **即時狀態回饋**：提供連線狀態指示燈、系統自動推播提示與對話歷程記錄，提供流暢的溝通體驗。

---

### 5. 📊 即時數據驅動主管後台 (Real-time Analytics Dashboard)
- **核心營運 KPI**：實時統計「今日總互動數」、「AI 自助解決數」、「中低風險開單數」與「高風險轉人工數」。
- **動態類別分佈長條圖**：即時呈現 6 大客訴類別案件量消長，輔助分析熱門問題點。
- **客訴案件動態趨勢圖**：以 8/1～8/19 歷史 100 筆為基準，依實際案件建立日期（`YYYY-MM-DD`）動態延伸時間軸，即時疊加長條高度與日期/件數 Tooltip 提示。
- **排單工單即時列表**：整合中低風險與轉人工案件，完整顯示客戶姓名、電話、描述細節、狀態與格式化日期時間（支援水平自適應捲動）。
- **客服負載平衡監控**：即時統計各客服人員處理件數與滿意度評分，輔助人力調度。

### 3. 核心資料模型規範 (Data Schema Specification)

#### ① 工單資料模型 (Ticket Schema)
```javascript
{
  id: "CT-2026-0101",          // 工單編號 (自動累加生成)
  category: "refund",          // 類別識別碼
  name: "王小明",              // 客戶姓名
  phone: "0912-345-678",       // 聯絡電話
  desc: "申請退票手續費計算有爭議...", // 客戶自填描述
  status: "處理中" | "轉人工處理中",  // 工單狀態
  time: "2026/08/30 16:50:30"  // 建立日期時間戳
}
```

#### ② 轉接案件模型 (Transfer Schema)
```javascript
{
  id: "TR-583921",             // 轉接唯一序號
  ticketId: "CT-2026-0101",    // 連動之工單編號
  category: "service",         // 客訴類別
  name: "陳小姐",              // 客戶姓名
  phone: "0988-123-456",       // 聯絡電話
  faqQ: "持餐券前往餐廳...",    // 客戶先前點選之案例問題
  faqA: "查核條款確認該餐券...",// 系統提供之解答
  desc: "商家態度超級惡劣，我要提告消保官!!!", // 用戶描述
  riskFlags: {
    keywords: ["提告", "消保官"], // 命中之風險關鍵詞陣列
    exclaimCount: 3             // 驚嘆號次數
  },
  time: "16:51:10",            // 轉接發起時間
  picked: true                 // 是否已被客服接手標記
}
```

#### ③ 即時對話模型 (Chat Message Schema)
```javascript
{
  role: "customer" | "agent" | "system", // 發話者角色
  text: "您好，我已看到您的訂單爭議，目前正在為您核查。", // 對話內容
  time: "16:52"                           // 訊息時間
}
```

### 4. 客訴類別與知識庫覆蓋規格 (Category Specifications)

系統內建 6 大核心業務客訴類別，均對齊實務營運情境：
1. **💳 退換貨與退款爭議 (`refund`)**：涵蓋行程變更、重複下單、鑑賞期爭議、退刷金流延遲等。
2. **📷 電子條碼無法掃描核銷 (`qr`)**：涵蓋現場閘機感應失敗、QR Code 破圖、條碼重複發放、過期判斷異常等。
3. **🔁 重複扣款與付款失敗 (`pay`)**：涵蓋信用卡分期預扣額度、第三方支付 (LINE Pay) 連線瞬斷重複扣款等。
4. **⚙️ 系統異常與無法取票 (`sys`)**：涵蓋簡訊驗證碼未達、熱門場次搶票伺服器超載退款等。
5. **🗣️ 商家服務態度與履約爭議 (`service`)**：涵蓋特約商家平假日加價爭議、履約品質落差處置等。
6. **⏳ 票券展延與過期處理 (`expire`)**：涵蓋過期手續費計算、過期轉等值購物金處置等。

## 🖥️ 介面與功能導覽 (System Walkthrough)

### 🎫 1. 客戶模式 (Customer View)
* **類別點選**：點擊 6 大分類按鈕，動態載入對應 FAQ 案例清單。
* **FAQ 展開與解答**：點選特定問答後，呈現「過去的處理結果」並提供自助回饋按鈕。
* **回饋分流**：
  * 點擊「**這個答案幫到我了**」：顯示感謝完成提示，更新自助解決指標。
  * 點擊「**還沒解決，我想描述狀況**」：展開姓名、電話與詳細情況填寫區。
* **送出判斷**：系統即時分析輸入字串，自動判斷產出「處理中」工單或升級至「轉人工處理中」狀態。

### 🧑‍💼 2. 客服模式 (Agent View)
* **待接手隊列**：左側清單即時顯示待處理的高風險案件，標記客訴類別與時間。
* **完整脈絡卡**：右側展示該案件之原始 FAQ 查詢、系統解答、客戶姓名/電話、客戶描述與紅色脈絡警示標籤。
* **接手與連線**：點擊「標記為已接手」按鈕後，即刻啟動雙向即時對話介面。

### 📊 3. 主管後台 (Supervisor Dashboard)
* **營運數據卡**：即時掌握互動總量、自助率、工單量與轉人工率。
* **視覺化圖表**：類別佔比動態進度條、動態日期軸之客訴案件趨勢長條圖（支援 Tooltip 檢視各日期件數）。
* **工單排程表**：清楚列出中低風險「處理中」與高風險「轉人工處理中」案件，包含姓名/電話、問題描述、精準單號分行排版與橫向捲動相容。
* **人力負荷監控**：掌握 5 位客服專員之處理案件數與服務滿意度。

## 🚀 快速開始與使用方式 (Quick Start)

### 需求條件 (Prerequisites)
- 任何現代主流瀏覽器（Google Chrome / Microsoft Edge / Mozilla Firefox / Safari 等）。
- 無需安裝 Node.js、Python 或任何後端伺服器環境。

### 執行步驟 (How to Run)
1. 下載或複製本專案資料夾。
2. 直接使用瀏覽器開啟 [`index.html`](file:///d:/Oris/Work/課程考試/20260721_AI時代的專案管理師養成班第01期/專題/個人/20260831/index.html) 或 [`AI客訴分流處理系統.html`](file:///d:/Oris/Work/課程考試/20260721_AI時代的專案管理師養成班第01期/專題/個人/20260831/AI客訴分流處理系統.html)。
3. 即可在三大分頁（客戶模式、客服模式、主管後台）之間切換並進行全流程互動體驗。
